### 清单的耗时（真机实测，顺便消掉一个悬念）

清单这一轮对每台机器是**并发**描述的（`Promise.allSettled`），不是一台一台来。
真机上两台机器：冷启动后第一拍 0.13 秒（此刻刚把两条 SSH 隧道拉起来），
之后 0.35–0.69 秒；期间无超时、无 `error` 字段，两台的状态都判对。

原先记着一个悬念：「机器多起来，冷启动会不会撞上 10 秒的清单预算」——并发之下
6 台也是同一个量级，不是一条一条累加。两台的实测放在这里；机器更多的情况没有
条件现场造，标为**未实测**，不拿两台的结果外推。

## 指纹闸门（真机验证，通过）

未登记指纹时中转**不建隧道**，机器显示 `credential: missing` / `reachable: false`，而不是
去连一个没核对过的主机。手工验证：`ssh root@100.84.120.35` 报 `Host key verification failed`，
而清单同时返回 200 与机器条目——拒绝发生在隧道层，不是整个接口挂掉。

## 验收发现的四处产品缺陷（全部已修）

### 1. 转发面的前缀路由**永远不会命中**

会话类接口登记的前缀自带结尾斜杠（`/threadharbor/relay/hosts/`），而宿主的前缀匹配是
「相等，或以 `前缀 + "/"` 开头」。于是它实际要求请求路径以 `//` 开头——**一条都不匹配**。
清单那条 exact 路由照常 200，于是现场症状是「清单正常、转发全 404」，极像配置或隧道问题。

修：前缀去掉尾斜杠，并在登记处加装载期断言（前缀以斜杠结尾直接抛错）。

### 2. 启动网址读错了日志形态

换凭据要读那台机器的启动日志拿令牌，而读取只认 `LAUNCH_URL=` 这行——那是**部署流程**写进
日志的标记。一台手工起的 dsh 只打印 `dsh web: <网址>`，于是 grep 命中的是**很久以前某次部署**
留下的旧标记：长度一样、内容不同，换凭据时对方回 401，而日志里明明有新鲜令牌。

修：两种形态都认，并按出现顺序取最后一条（日志只追加，位置就是时间）。

### 3. 会话列表少了一层参数壳

上游 RPC 的描述符要求每个方法都有一个 `_request` 请求对象，清单这个方法传的是空对象，
上游回 `args fields do not match the descriptor: missing "_request"`。中转把它压成
`machine-error`，看起来像「那台机器坏了」。

修：补上空壳，并加用例钉住参数形状。

### 4. 事件面把裸 TCP 当 WebSocket 用（这一面从未连通过）

升级处理器拿升级上来的**裸 socket** 直接 `send(JSON…)`：既没人写 101 握手，也没有帧
编解码——那不是 WebSocket 帧。手机侧的表现是永远停在「连接中」，而这一面**一个用例都
没有**，所以它坏了没人知道。真机用 curl 发 Upgrade 请求，连一个应答头都收不到。

修：升级面交给 ws 的 noServer 模式做握手与帧（它本来就是本包已声明的依赖），协议本身
（ready / item / 应答）仍留在中转层。新加的用例是真的 http 服务 + 真的 ws 客户端走完整握手，
去掉握手立刻变红。

### 5. 有界化等于静默（两次都栽在这）

`machine-error` 这类内部故障，手机只拿到有界文案是对的——但那之前的注释写着「细节进日志」，
而**代码里没有任何地方写日志**。结果就是：真机上一句 machine-error，谁也查不下去。

修：加了内部故障落点（hostId + 动作 + 错误首行，不含凭据），并用真机抓到了上面第 3 条的原文。
注意落点选 `console`：DSH 自己的 logger 输出不进运维真正在读的那份追加日志（真机实测搜不到）。

## 部署形态（修正）

**`known_hosts` 的别名没有任何途径能让运维知道。** 中转按 `threadharbor-<sha256(target\0ssh端口) 前24位>`
这个**算出来的别名**查指纹，而不是按 IP。原先 `scripts/relay-setup.sh` 只写「known_hosts 里要有
这台机器的指纹」——照做的人用 `ssh-keyscan` 写进的是 IP 条目，中转查不到，于是那台机器永远
「需先确认指纹」，而症状看起来与「机器离线」几乎一样。

修法：脚本现在**把这个别名算出来并打印**，连同登记命令一起给出（`--ssh-port` 也算进去，
因为别名把 SSH 端口纳入哈希）。真机上按脚本给的值登记后别名核对一致
（`threadharbor-563336ce4c9a9a72687422c7`），本地与云主机算出同一个值。用例 3 条钉住。

## 为什么最初「隧道建不起来」——两次都排错了方向

最初清单是 `reachable:false`，没有任何原因。排查时我先后排除了指纹、SSH 可达、隧道命令本身，
手工跑 `ssh -N -L …` 都是通的，于是**停在「插件内部有问题」这个结论上**——其实方向就错了。

真正的原因是 known_hosts 里那一行**只有别名、没有公钥**（我上一轮追加时把公钥部分丢了），
中转查指纹查不到，于是否决建隧道。证据是最后给清单补上的 `reason`/`detail` 两个字段：
一眼就是 `fingerprint-unapproved`，并直接写出了目标地址。

**教训**：`reachable:false` 是个不吭声的故障——没有信号，现场只能逐个排除，而且很容易
把自己排除过的方向当成已排除的方向。给这类出口**留一个自报状态的字段**，比事后推理便宜得多。

## 转发面：另外两处只在真机上暴露的错

### 7. 会话前缀只放行 GET，发消息与中断在真机上是 405

看（清单、历史）和发（prompt、cancel）是一条前缀路由，但登记时只写了 GET。现场表现
特别有欺骗性：清单正常、能读历史，只有「发」的动作永远 405，看着像手机端按钮没反应。

### 8. 三个端点的参数形状是照感觉写的

线上的字段名就是宿主方法声明的**形参名**（只有 `list` 写作 `_request`，别处都不带下划线），
而参数对象的内容照抄 `packages/dsh-client` 里那份已经在用的实现：

| 端点 | 中转原先发的 | 宿主要的 |
| --- | --- | --- |
| `session/list` | `{_request:{}}` | `{_request:{}}` ✓ |
| `session/page` | `{_request:{sessionId}}` | `{request:{address:{kind:'session',sessionId},throughSeq:-1}}` |
| `session/cancel` | `{_request:{sessionId}}` | `{request:{sessionId}}` |
| `session/prompt` | `{request:{sessionId,text}}` | `{request:{requestId,sessionId,mode:'queue',content:[{type:'text',text}]}}` |
| `$events/result` | `{clientId,eventId,outcome}` | ✓ |

真机上的证据：修好后三个端点都不再报描述符不匹配，而是回 `session "x" not found`——
**参数形状被接受了**，只是那个会话本来就不存在（这是拿一个假会话号打的）。

### 9. 落点选了 console，等于没落

上一条修完立刻被这条挡住：`console.warn` 的输出**没有出现在任何日志文件里**（插件跑在
worker 里）。落点最终改成 state.json 旁边那个只追加的 relay.log——这也是把第 3 条的原文
捞出来的方式。

## 评审的反向验证又挖出三处「有方法，但没人调」

这类错有一个共同形状：**被测的方法本身是对的，被测的那个方法也是绿的，缺的
是把它接进生产的那一行**。单测问的是「这个方法对不对」，没人问「谁调它」。

### 10. 历史分页参数被丢掉：手机在中转模式下翻不动历史

手机是拿游标一页一页要历史的（`pageMessages(hostId, sessionId, throughSeq, maxMessages)`）。
中转这边把游标写死成 -1，于是每一页都在问「整段」——界面表现为翻不动，或者翻回去
又是同一页。直连模式没这个问题，所以真机上要走到中转那条路才看得见。

### 11. `Relay.reconcile` 从来没被生产调用过

订阅对账（哪台在线就挂哪台）是「启动时离线的机器上线后自己补上」的唯一时机。
方法写了、也有用例直接调它，但装配层从来没接线——那台机器清单上明明是通的，手机
却收不到它的任何动静，直到中转重启。

### 12. 事件面的升级路由不可卸载

`registerUpgrade` 的返回值（disposer）被丢掉了，插件重载时宿主会撞上「重复登记
升级路由」，整个中转从此起不来。三条 HTTP 路由都走了 `ctx.effect`，只有它没有。

三条都补了**装配层**的用例（不是方法层的）：盯的是「谁调它」，改动后立刻变红。

### 13. 应答路径也在「有界化等于静默」里栽了一次（现场发现，非评审）

真机上连发三次失败的应答：机器没登记 → `not-found`；机器登记了但服务没起 →
`answer-failed`；服务在但事件不存在 → 上游居然回 `ok`。前两次在手机上分别看到
「应答失败」和「应答失败」，**日志一行都没多**。

原因是应答这条路上游的失败全部被折成 `{ok:false, message}` 而不是抛，手机上三种
情况长得一模一样，细节没有出口——和第 9 条是同一个坑，只是那次只给转发那侧挖了。

修：应答失败也落一行（哪台机器、哪个事件、上游的原话）。真机复验：`应答 japan01
失败（事件 e1）：answer 在收到 ready（clientId）之前被调用，未发送`——顺带把
「服务没起」这件事的真正原因也说清了。

### 14. 停机不收隧道：热重载之后新一代抢不到自己的固定端口

自己通读代码时发现的（不是评审，也不是现场）。真机上栽过同一个坑的另一面：
用 nohup 起的旧实例，父进程退出**不会**带走 ssh 子进程，端口一直被占。换成
systemd 之后整机重启有 `KillMode=control-group` 兜着，但**插件热重载**没有这层
保护——而重载这条路我为了另一条理由刚补过（升级路由的处置器）。

三处都缺：装配层不登记停机处置器；即使登记了，隧道池也没绑真正的收尾钩子
（`closeAll()` 只清内存句柄）；就算绑了，排队版还是会把收尾推到微任务之后，
而宿主的处置器是**同步调用、不等 Promise** 的。

修：处置器当场调同步版收尾（`closeAllNow`），并把 SSH 管理器的 close 绑上。
每一步都有用例，且每条用例都做过反向验证——排队版、没绑钩子、不登记处置器、
不退订、只清句柄，五种改法都会立刻变红。

真机复验：重启后两台机器的隧道各一条、端口仍是 41100/41101、凭据复用，
清单状态与之前一致。

## 第二台机器带来的第六处缺陷：指纹登记命令产出 ssh 不认的行

`scripts/relay-setup.sh` 给的登记命令是「把别名顶到 `ssh-keyscan` 的输出前面」。但
keyscan 输出的**第一段就是主机名**，直接拼上去会得到 `别名 主机名 keytype 公钥` 四段，
ssh 解析时把主机名当成 keytype，整行散掉——现象是「明明登记了，那台机器还是提示指纹未
登记」。加上 `-H`（当时的想法是隐藏主机名）更糟：它哈希掉的正是主机名那一段，而中转是
按**别名**查的，别名从此对不上。

修：命令改成只取第 2、3 段再把别名顶上去，并去掉 `-H`。用假 keyscan 输出把脚本给的
命令走一遍，断言产出的行确实是三段——比对脚本文本测不出这件事，因为旧命令的字符串
完全「正确」。

## 从 nohup 换成 systemd（真机实测的必要改动）

原来用 `setsid nohup` 起实例，连着重启几次之后，**上一代的 ssh 隧道还活着**并占着中转的
固定端口；新实例随即报「端口已被其他进程占用」并拒绝自动换号（换了号，已存凭据就对不上地址），
清单于是一直显示不可达。父进程退出不等于子进程被收走——这正是 nohup 给不了的东西。

改用 `deploy/threadharbor-relay.service`（`KillMode=control-group`）：stop/restart 收走整组子进程，
机器上别的 ssh（japan01 等既有隧道）不受影响。实测重启后 41100 无残留监听，下一次请求按需重建。

**顺带查出第二件事**：这台主机上**没有私钥文件**，SSH 自连一直是靠我交互会话转发进来的 agent
（`SSH_AUTH_SOCK`）。systemd 起的实例没有这个环境变量，于是 `Permission denied (publickey…)`。
给中转配了专用私钥（`/root/.ssh/th-relay`，公钥进 `authorized_keys`，配置里 `identityFile`）。

这条要写进准备清单：**中转要有自己的私钥，不能依赖交互会话的 agent**。

## 部署形态（本次实测确认的事实）

- 插件从**包自带的那份补丁文件**（`/root/threadharbor/cordis.patch.yml` 的 `insert:` 列表）装载，
  不是 profile 的 `cordis.patch.yml`。profile 那份**先于** bundle 应用，在里面引用一个还没
  插入的 id 只会得到一条 warn，且配置不会生效——中转的配置因此放在 bundle 层。
- 机器条目必填 `logPath`（凭据过期时中转从那里读新的带令牌网址）。
- `/threadharbor/relay/*` 走 DSH 配对准入：只带 nginx 口令访问返回 `401 unauthorized`，
  这是对的——配对 cookie 仍是第一道，口令只是第二道。
- `/threadharbor/mobile/hello` 不走准入。
