# 手机端访问（Android）

ThreadHarbor 的手机端是 DSH 直接服务的独立网页：手机装上 Tailscale 加入同一私网，
打开某台机器的 `https://<机器名>.<tailnet>.ts.net/threadharbor/mobile/`，即可看那台机器的
会话、发消息、批准权限请求、停止回合。桌面端行为不变，DSH 仍只监听回环。

本文描述的是**已实现的现状**（核对时间 2026-10-15）；早期 gateway/hostd 时代的接法设想
已随多主机迁移废弃，设计取舍见
[mobile-entry 设计](./superpowers/specs/2026-10-14-mobile-entry-design.md)。

## 网络通道

- 每台机器各跑一个 DSH，只听回环；手机可达性由 `tailscale serve --bg <dsh端口>` 提供：
  把回环端口发布为 `https://<机器名>.<tailnet>.ts.net/`（Let's Encrypt 证书，
  仅 tailnet 内设备可达）。
- DSH 进程启动时要带 `--trusted-host <机器名>.<tailnet>.ts.net`——不加的话，手机浏览器
  在该域名下的一切 API 调用都会被 403 拒绝。
- 一键配置：`scripts/mobile-setup.sh <dsh端口>`（读本机 ts.net 域名、执行 serve、
  打印上面两步要抄的配置）。逐步手工配置见
  [install.zh.md](./install.zh.md) 的「手机通道」一节。

## 配对与凭据

- 每台机器各自配对一次。桌面端侧栏的「手机配对」面板显示二维码，内容是本机
  `/threadharbor/mobile/pair-url` 接口返回的带进程令牌的手机页网址；
- 面板要求本机 DSH 配置了 `mobileOrigin`（手机页根网址，如 `https://mac1.example.ts.net`）。
  没配时面板给配置指引而不是空白。该字段只收 https 源（不带路径、查询、结尾斜杠），
  写错时 DSH 装载即失败并说明原因；
- 手机扫码打开网址 → DSH 的官方授权入口把 URL 里的令牌换成签名 cookie（303 落回手机页）
  → 配对完成。此后同源 cookie 就是手机与桌面同一份凭据；
- cookie 默认 30 天，跨 DSH 重启有效（签名密钥持久化）；令牌随进程轮换，只在扫码那一刻
  消费一次；换手机、清浏览器数据、凭据过期 → 重新扫码即可；
- 多台机器的 cookie 互不冲突，多部手机同时配对互不影响；
- 二维码和网址里带着进程凭据，只给本人手机扫，不要截图外传。

## 手机页

- 首屏是**主机**页签：本 tailnet 的机器名单（来自提供页面的机器查一次
  `tailscale status`），逐台标注在线/离线、是否在跑 DSH（服务端对每台做 2 秒短超时
  探测，结果缓存 5 秒）。名单只作展示，第一版不跨机连接——要看哪台机器的会话，
  就打开哪台的手机页；
- **会话**页签是本机会话列表（可「加载更早」按批多亮），点开看内容；
- 会话里可以发消息、对权限请求批准/拒绝、停止进行中的回合；
- 断线自动重连；收到会话事件广播时整页补拉一版最新状态（第一版不做精确断点续传）。

数据通道全部是 DSH 官方 API 与 WebSocket 事件流，手机没有自己的协议。

## 云主机通道（手机不装 Tailscale）

如果这台页面是由一台云主机中转出来的（而不是直连某一台机器），界面上的差别只有一个：首屏先列机器，点一台进去才是那台机器的会话列表。往下走的一切操作——看历史、发消息、批权限、停止回合——与直连完全一致。

**会话名与待批横幅上会带机器名**，因为两台机器可能同时有待批事项，不标明来源只能靠猜。点「同意/拒绝」时，请求会发回**发出这条请求的那台机器**，不是当前正在看的那台。

**打不开时按这三步查**（顺序是有讲究的，从最常见、最容易排除的开始）：

1. **VPN 通道占着。** 手机上如果还连着 Tailscale 或别的 VPN，它会接管全部流量，域名可能被解析到私网地址或被直接拦下。**完全退出 VPN 再试**——这是最常见的一条，也是最容易误判成「站点挂了」的一条。
2. **代理直连规则。** 手机装了代理类 App 时，它们默认把全部流量也送进代理，于是请求带着错误的 Host 或走错出口。把这个域名加进代理的**直连/排除**名单，再试。
3. **证书信任。** 证书是公网机构签的、有效期 90 天。如果浏览器仍报证书警告，通常是系统时间不对（时间偏差过大）或中间有抓包——先核对手机系统时间与自动校时。

三步都排掉还打不开，回来找运维要这两样：入口域名（形如 `https://<子域>.<主域>`）与口令。**不要把口令截图外传。**

页面上有一处值得先说：**顶栏那个「事件通道」显示「未连接」时，待批横幅不会出现、别人的新消息也不会自动冒出来**（自己点「发送」后的刷新不受影响）。它连的是站点自己的加密 WebSocket 地址；一直连不上时先看是不是被浏览器或手机的省流量/隐私策略挡了 WebSocket，其余往下按上面三步查。

三步都排掉、页面能开但**某台机器点不进去**，那是中转侧的事，找运维看一个文件：`relay.log`（与 `state.json` 同目录，只追加）。手机上只会看到「这台机器现在有问题」这类有意的简短提示，真正的原因在那份日志里——转发参数不被上游接受、SSH 隧道开不出来、凭据换不到，各有一行。**不要让手机去猜这些。**

## 出问题时的提示

| 手机页提示 | 原因 | 处理 |
| --- | --- | --- |
| 直连：「这台主机还没信任你」（HTTP 403） | 域名不在该机的 `--trusted-host` 名单里 | 按安装文档把 `--trusted-host` 加上并重启该机 DSH |
| 直连：「还没配对」（HTTP 401） | 没扫过码，或凭据已过期 | 打开该机桌面端的「手机配对」面板重新扫码 |
| 中转：「中转站还没信任你」（HTTP 403） | 域名不在**中转站**的 `--trusted-host` 名单里 | 在中转站上按安装文档加上并重启它的 DSH |
| 中转：「还没跟中转站配对」（HTTP 401） | 没扫过码，或**手机与中转站**的凭据已过期 | 打开**中转站那个页面**（入口域名 + `/threadharbor/mobile/`）的「手机配对」面板重新扫码。⚠️ 别用你自己电脑上 ThreadHarbor 桌面端的二维码——那会把手机配到另一台机器上，打开的是它的直连页，中转整条链路白走 |
| 「连不上主机」 | 手机或该机不在线 | 检查两端 Tailscale 连接后重试 |
| 主机区显示「本机 Tailscale 不可用：…」 | 提供页面的机器查不了 tailscale 命令 | 名单暂缺，会话等功能不受影响 |
| 机器条目显示「需先确认指纹」 | 中转还没登记那台机器的 SSH 指纹 | 跑一遍准备脚本，按它打印的**登记命令**把那行写进 `known_hosts`（照抄，别自己拼） |
| 机器条目显示「隧道通但凭据没换到」 | 连得上那台机器，但换不到进它的凭据 | 通常是那台机器的 DSH 没起或刚重启；同样看 `relay.log` 的对应行 |

## 安全边界

- 不新增无凭据控制面：手机页之外仅有的两个接口（主机清单、配对网址）都先过 DSH 官方
  准入，未通过即 401/403；手机页的应用壳本身公开返回——它同时承担配对引导屏的职责，
  内容不含秘密，数据能力全部在官方 API 围栏之后；
- 手机的权限边界 = DSH 官方 API 在操作者身份下的边界，不放大、不另设；
- 私网边界：ts.net 地址仅 tailnet 内设备可达，可再叠加 Tailscale 的设备授权。
