# 手机端访问（Android）

ThreadHarbor 的手机端就是 DSH 的完整网页：手机装上 Tailscale 加入同一私网，配对后打开
`https://<机器名>.<tailnet>.ts.net/`，看到的是和桌面端同一套界面——会话、发消息、批权限、
停止回合、主机管理都在，手机屏幕上侧栏收成抽屉。多主机也在同一个页面里切换：从任意一台
已接通的机器都能整页跳到其余主机，像在本机操作一样。

本文描述的是**已实现的现状**（核对时间 2026-10-22）；早期 gateway/hostd 时代的接法设想
已随多主机迁移废弃，设计取舍见
[mobile-entry 设计](./superpowers/specs/2026-10-14-mobile-entry-design.md)。

## 网络通道（直连）

- 每台机器各跑一个 DSH，只听回环；手机可达性由 `tailscale serve --bg <dsh端口>` 提供：
  把回环端口发布为 `https://<机器名>.<tailnet>.ts.net/`（Let's Encrypt 证书，
  仅 tailnet 内设备可达）。
- DSH 进程启动时要带 `--trusted-host <机器名>.<tailnet>.ts.net`——不加的话，手机浏览器
  在该域名下的一切 API 调用都会被 403 拒绝。
- 一键配置：`scripts/mobile-setup.sh <dsh端口>`（读本机 ts.net 域名、执行 serve、
  打印信任主机与「手机访问地址」两步）。逐步手工配置见
  [install.zh.md](./install.zh.md) 的「手机通道」一节。
- **手机访问地址**：桌面端「手机配对」面板下面有一个「手机访问地址」编辑框，填这台机器
  对手机/其他电脑的源，例如 `https://<机器名>.<tailnet>.ts.net`。保存即生效（不用重启
  DSH），配对网址会按它重新生成；留空则回到「按当前页面地址生成」。它只收源：协议、
  主机、端口，不带路径、查询或结尾斜杠；支持 http/https，推荐 https。
- 如果面板拿到的地址是 `localhost`/`127.0.0.1`，说明页面是从本机打开的，会先提示
  「这个地址只在本机有效」——把「手机访问地址」改成 tailnet 或局域网地址再保存。

## 多主机：在任意一台 DSH 上管理其余主机

- **主机面板**按行列出本机认得的主机。行首是状态圆点和名称；有打开地址的主机，点整行
  就**整页切到那台机器的界面**（地址形如 `/threadharbor/gateway/<主机标识>/`），行尾的
  「设置」仍进本页的主机设置。没有打开地址的主机（本机、从未打开过的登记、还没部署的
  机器）点行落到设置页，那里是补地址、部署、连接的地方。
- **远端页顶部的主机切换器**：下拉框列出「当前主机」「本机」和其余已登记主机，旁边还有
  「回本机」。换主机不用回到主机面板，也不会开新标签页留下两套并行界面。
- 网关是**同源反向代理**：浏览器看到的仍是这一台的地址，普通 DSH API 调用按前缀转到
  那台主机；登录 cookie 留在提供页面的机器上，不下发给浏览器，也不接收浏览器传来的
  任意网址。
- **主机之间自己交换登记簿**：浏览器打开页面时报到自己的身份（标识 + 显示名），宿主据此
  铸出带令牌的打开地址，再把「自己 + 自己知道的主机」推给登记簿里的每一台。对端只补
  缺失的条目、只为同一地址刷新令牌，不改本机已登记的地址、SSH 事实与读数。登记或身份
  变化后几秒内推送，另有每十分钟一次的刷新。
- 因此**每台新装好的机器要先正常打开一次它的页面**（桌面打开或手机配对都算），让它报到；
  其余主机随后会收到它的入口。只在别人那里登记、却从未打开过的机器没有打开地址，
  网关进不去。

## 配对与凭据

- 在要直连的机器上配对一次。桌面端侧栏的「手机配对」面板显示二维码，内容是本机
  `/threadharbor/federation/pair-url` 接口返回的**完整 DSH 界面**带令牌网址；
- 面板依赖上面的「手机访问地址」生成二维码；没配且当前页面是本机地址时，面板给配置
  指引而不是空白；
- 手机扫码打开网址 → DSH 的官方授权入口把 URL 里的令牌换成签名 cookie（303 落回
  完整界面）→ 配对完成。此后同源 cookie 就是手机与桌面同一份凭据；
- 只配对**一台**也够用：用那台的主机切换去其余已接通的主机。若某台机器不在它的名单里，
  或名单上的条目没有打开地址，先照上一节把那一台打开一次；
- cookie 默认 30 天，跨 DSH 重启有效（签名密钥持久化）；令牌随进程轮换，只在扫码那一刻
  消费一次；换手机、清浏览器数据、凭据过期 → 重新扫码即可；
- 多台机器的 cookie 互不冲突，多部手机同时配对互不影响；
- 二维码和网址里带着进程凭据，只给本人手机扫，不要截图外传。

## 手机上的界面

- 宽度 ≤1023px 时，侧栏以**抽屉 + 遮罩**出现，主内容占满整宽；点遮罩、或点完侧栏里的
  导航后抽屉自动收起。收起状态仍归 DSH 自己的布局服务管，用的是它自己的折叠按钮。
- 抽屉里就是 DSH 的完整侧栏：会话、项目、主机面板都从那里进；主机面板里的列表、设置、
  部署信息与桌面端同一套。
- 宽度 ≤640px 时进一步精简内容：主机列表隐去 IP 列、边距收窄、行高加大便于点按；表单
  占满宽度；输入框用 16px 字号避免 iOS 聚焦时自动放大；长地址、公钥、只读值自动换行。
- 远端主机页顶部保留 44px 的主机切换条（窄屏隐藏「主机」字样），下拉框用 16px 字号。
- 会话流、权限请求、停止回合、事件通道全部是 DSH 官方界面与官方 API；断线重连也由
  DSH 自己处理，手机端没有自己的协议。

## 云主机通道（手机不装 Tailscale）

这是一条**独立通道**：由一台常开的云主机当中转，它自己出精简版手机页
（`https://<入口域名>/threadharbor/mobile/`），不是上面那套完整界面。它的配对、配置与
故障排查仍走中转自己的 `mobileOrigin` 与 `pair-url`，与直连的「手机访问地址」互不影响。

如果这台页面是由云主机中转出来的（而不是直连某一台机器），界面上的差别只有一个：首屏先列机器，点一台进去才是那台机器的会话列表。往下走的一切操作——看历史、发消息、批权限、停止回合——与直连完全一致。

**会话名与待批横幅上会带机器名**，因为两台机器可能同时有待批事项，不标明来源只能靠猜。点「同意/拒绝」时，请求会发回**发出这条请求的那台机器**，不是当前正在看的那台。

**打不开时按这三步查**（顺序是有讲究的，从最常见、最容易排除的开始）：

1. **VPN 通道占着。** 手机上如果还连着 Tailscale 或别的 VPN，它会接管全部流量，域名可能被解析到私网地址或被直接拦下。**完全退出 VPN 再试**——这是最常见的一条，也是最容易误判成「站点挂了」的一条。
2. **代理直连规则。** 手机装了代理类 App 时，它们默认把全部流量也送进代理，于是请求带着错误的 Host 或走错出口。把这个域名加进代理的**直连/排除**名单，再试。
3. **证书信任。** 证书是公网机构签的、有效期 90 天。如果浏览器仍报证书警告，通常是系统时间不对（时间偏差过大）或中间有抓包——先核对手机系统时间与自动校时。

三步都排掉还打不开，回来找运维要这两样：入口域名（形如 `https://<子域>.<主域>`）与口令。**不要把口令截图外传。**

页面上有一处值得先说：**顶栏那个「事件通道」显示「未连接」时，待批横幅不会出现、别人的新消息也不会自动冒出来**（自己点「发送」后的刷新不受影响）。它连的是站点自己的加密 WebSocket 地址；一直连不上时先看是不是被浏览器或手机的省流量/隐私策略挡了 WebSocket，其余往下按上面三步查。

三步都排掉、页面能开但**某台机器点不进去**，那是中转侧的事，找运维看一个文件：`relay.log`（与 `state.json` 同目录，只追加）。手机上只会有**一句说明下一步的话**（例如「那台机器没接住这次请求，看它上面 DSH 的状态」），不会把中转内部的错误代号甩给你；中转要是回了个不认识的代号，那一句里会原样带上它——藏起来等于让故障变成「什么都没发生」。真正的原因在那份日志里——转发参数不被上游接受、SSH 隧道开不出来、凭据换不到，各有一行。**不要让手机去猜这些。**

## 出问题时的提示

| 手机页提示 | 原因 | 处理 |
| --- | --- | --- |
| 直连：打开域名 403 | 域名不在该机的 `--trusted-host` 名单里 | 按安装文档把 `--trusted-host` 加上并重启该机 DSH |
| 直连：HTTP 401 / 回到登录入口 | 没扫过码，或凭据已过期 | 打开该机桌面端的「手机配对」面板重新扫码 |
| 「这个地址只在本机有效」 | 「手机访问地址」是 `localhost`/`127.0.0.1` | 改成 tailnet 或局域网源并保存 |
| 手机能打开，但某台主机点不进去 | 那台没有打开地址、不在线，或还没报到过 | 先正常打开那台页面一次；再检查那台 DSH 是否在跑 |
| 中转：「中转站还没信任你」（HTTP 403） | 域名不在**中转站**的 `--trusted-host` 名单里 | 在中转站上按安装文档加上并重启它的 DSH |
| 中转：「还没跟中转站配对」（HTTP 401） | 没扫过码，或**手机与中转站**的凭据已过期 | 打开**中转站那个页面**（入口域名 + `/threadharbor/mobile/`）的「手机配对」面板重新扫码。⚠️ 别用你自己电脑上 ThreadHarbor 桌面端的二维码——那会把手机配到另一台机器上，打开的是它的直连页，中转整条链路白走 |
| 「连不上主机」 | 手机或该机不在线 | 检查两端 Tailscale 连接后重试 |
| 主机区显示「本机 Tailscale 不可用：…」 | 提供页面的机器查不了 tailscale 命令 | 名单暂缺，会话等功能不受影响 |
| 机器条目显示「需先确认指纹」 | 中转还没登记那台机器的 SSH 指纹 | 跑一遍准备脚本，按它打印的**登记命令**把那行写进 `known_hosts`（照抄，别自己拼） |
| 机器条目显示「隧道通但凭据没换到」 | 连得上那台机器，但换不到进它的凭据 | 通常是那台机器的 DSH 没起或刚重启；同样看 `relay.log` 的对应行 |

## 安全边界

- 直连不给手机另开控制面：完整界面、配对网址、主机报到/推送全部先过 DSH 官方准入，
  未通过即 401/403；
- 网关只认登记簿里**有打开地址**的主机，且地址必须与该机的登记地址同源；浏览器传来的
  网址一个字节都不采信。登录 cookie 留在提供页面的机器上；
- 手机的权限边界 = DSH 官方 API 在操作者身份下的边界，不放大、不另设；
- 私网边界：ts.net 地址仅 tailnet 内设备可达，可再叠加 Tailscale 的设备授权。
