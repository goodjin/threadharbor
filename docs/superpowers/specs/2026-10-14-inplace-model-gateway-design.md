# 原地回答：外部 agent 作为模型网关（设计）

- 日期：2026-10-14
- 状态：已定方向（用户拍板"原地回答"）
- 前置：`docs/bugfix/2026-10-14-codex-switch-collapsed-base-id.md`（切换链已通，但分叉体验被否）

## 问题

一个已开始的会话（预设已被宿主锁定）里，用户在模型选择器挑了某个外部 agent 的模型。
现行做法是分叉新会话、搬运对话、在新会话里提问——用户反馈两条都不接受：
要求用户"到新会话继续"，且新会话在界面上不可见。

## 决策

外来对话回合的模型请求**原地回答**：外部 agent 作为"模型网关"，把自己的回答以
原生模型流的形态送回当前会话的当前回合。界面不动、会话不搬家、对话连续。

取舍（已向用户说明并确认）：
- 该会话内外部 agent 只作为**模型**回答；它自带的工具体系不映射为宿主工具调用，
  其工具活动以内容事件照实记录（同驱动会话的卡），回答文字流入原生消息。
- 想要外部 agent 的完整体验（自己的工具、审批、模式），新建该预设的会话——那条路不变。

## 机制

1. **触发**：目录适配器 `stream()` 收到对话回合请求（无 `purpose`、带 `sessionId`），
   且该会话不被本行驱动（驱动会话的步骤被替换，根本不会走到这里——到达即异常，保留原诊断）。
2. **外部对话生命周期**：每个 DSH 会话懒开一个外部对话（transport + client + 回合运行器）。
   - 首个请求：以转录打底（现有 handover 打底机制，同分叉路径用过的装配），
     再提交本回合问题——agent 看到的是"之前的对话 + 新问题"。
   - 后续请求：只喂增量（上一游标之后的新用户侧文本；assistant 消息是它自己说的，跳过）。
   - 宿主重启后句柄自然丢失；下一请求重新打底，对话无缝续上（外部 agent 的内部状态
     不跨宿主续命，与驱动会话现状一致）。
3. **投影**：ACP 会话更新 → 宿主 `StreamChunk`（block-start / text-delta /
   reasoning-delta / block-end / finish）。文字与推理照映；工具调用不翻译为宿主
   工具调用；回合结果映射 finish 原因（completed→end_turn，其余按错误拒绝）。
4. **权限**：沿用 `bridgePermissions` 与宿主审批策略，同驱动会话。
5. **模型**：请求携带的模型名原样传（基础名已真机验证可用）；带 `reasoningEffort`
   且模型名无档位后缀时拼回后缀。
6. **并发**：同一 DSH 会话同时至多一个进行中的提示；第二个并发流排队。
7. **后台用途**（起标题/压缩）：维持拒绝（标题回退首条消息文本，同驱动会话现状）。
8. **退役**：外来路径的分叉/切换链撤下（`agent-switch/handover` 结束不再由外来请求产生）；
   switch-mount 的服务校验、已驱动自检等保留。旧分叉会话已存在的不动。

## 不做（v1）

- 外部 agent 工具调用 ↔ 宿主工具的互相翻译。
- usage 块映射（外部 agent 的 token 统计口径不一）。
- 外部对话跨宿主重启的持久化。
- DSH 会话结束即关外部进程（监听 `session/end` 类事件尽力关闭；漏关接受，进程空闲自查兜底）。

## 实现偏差（记录于落地时）

- **工具卡不写会话日志**：网关从目录适配器深处被调用，拿不到步骤的内容写入端口；
  外部 agent 自己的工具活动 v1 不进日志、也不混入回答文本（改为沉默执行，
  权限照常走宿主审批）。回答只含文字与推理。后续若要可见，
  需要把内容写入端口经 deps 传入网关，属于独立增量。
- **会话收尾**：挂在 `workspace/session-stop` 上关网关外部进程（与驱动会话同路），
  未单独监听 `session/end`；归档即停已覆盖主要场景。

## 验收

- 已开始的原生会话里选 codex 模型并发问：回答原地流式出现，会话不换、无新会话产生。
- 第二问只喂增量（外部侧不重复收到第一问）。
- 起标题请求不触发外部提示。
- 真机：codex 一问一答 + 追问（基础名与带档位名各一）。
