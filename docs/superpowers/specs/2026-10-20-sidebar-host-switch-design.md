## 问题（为什么现在做）

插件的浏览器半边把自己的树按优先级 -10 注册进 `sidebar.workspaces`，遮蔽了 DSH 原生的
工作区浏览区（原生默认 0，数字小者渲染）。用户对比原生后发现左栏缺了一整套能力，
其中最先被察觉的是「新建项目」——它在 DSH 里叫「添加工作区」。

盘点两侧后的缺失清单（插件对照原生，逐条有据）：

| 缺失项 | 原生做法 |
|---|---|
| 新建项目（添加工作区） | 顶栏 + 号 → 选目录 → 建工作区 → 直接开会话；只能选目录，无文本兜底 |
| 取消归档 | 归档行上 ⋯ 菜单与行尾按钮都可取消 |
| 分组方式三档 + 「未分组」桶 | 按工作区 / 按工作区树 / 单列表，选择持久化 |
| 行尾快捷按钮、悬停卡、双击改名 | 悬停出归档与置顶按钮；悬停 800ms 出完整标题、相对时间、状态、复制 |
| 拖拽排序 | 会话同组内、工作区同级之间可拖，顺序持久化在宿主 |
| 树内快捷键 | ⌘K 搜索、⌘O 新增、⌘G 重命名、⌘F 分叉、⇧⌘A 归档 |
| 操作反馈 | 「停止并归档」清单弹窗、归档成功给撤销、重名报错、分叉失败提示 |
| 侧栏收窄成窄条 | 变成新增与搜索两个图标 |
| 第三方往会话行挂东西 | `sidebar.session.row.leading` / `hover` 两个座位；定时任务的时钟标记与任务列表就挂在这里 |

插件**多出来**的（主机分组、跨主机搜索、远端动作代理、未部署提示、活跃标记、手机配对、
配额胶囊、会话 id 条）是当初换掉原生树换来的，不在缺失清单里。

## 根因：插件拿不到那 5 个子插槽

原生树不只渲染内容，它还**声明**了 5 个子插槽：选目录流程、会话 ⋯ 菜单条目位、行尾
按钮位、行前装饰位、行悬停卡位。这些声明跟原生那次注册写在同一次调用里，所以原生那份
注册**一定会发生**，哪怕它永远不渲染——优先级只决定谁渲染，不决定谁注册。

插槽系统对子插槽是**先到先得**：第二次声明同一个子插槽的注册会抛错（`slot "X" is
already declared`）。于是「插件接管这 5 个子插槽」在当前机制下拿不到：插件后注册则插件
崩，插件先注册则 **DSH 自带的包当场崩**，而顺序由 Cordis 的加载次序决定、不可控。

「干脆禁用原生那个包」也不是路：全仓库有 11 个包引用它提供的服务（对话、聊天、定时任务、
子代理、工作流运行、两个目录选择器、侧栏、agent preset、agent team、runner），禁用会让
它们的注入永远等不到，那些功能**静默消失**，比现在更糟。

结论：只要插件还想遮蔽原生树，就既补不齐清单，也拿不回第三方注入。**要补齐，就得让位。**

## 决策（已拍板）

1. **侧栏还给原生。** 插件不再遮蔽浏览区，缺失清单里的九项全部由原生承担，且以后 DSH
   升级带来的新能力自动跟随。
2. **跨主机浏览改成主机切换。** 侧栏底部动作区放主机选择器，点某台主机后**整页导航**到
   那台机器的网关路径，于是侧栏就是它自己的原生树。跨主机汇总视图退役。
3. **回本机的入口由网关注入。** 切过去后页面是对方的，侧栏也是对方的；不依赖对方是否
   装了本插件，网关在改写页面时注入一个克制的「当前主机 + 回本机」入口。
4. **远端不做拖拽排序。** 其余远端能力（建项目、取消归档等）由那台机器自己的原生界面承担。
5. **目录权限与本机一致。** 任何能在某台主机上操作的人，可以在同一权限下浏览该主机的
   任意路径。与网关既有的信任模型一致——它已经把登记主机的整条接口按路径转发，且早就能
   改工作区、删工作区、分叉会话。
6. **退役分两步。** 先默认不注册并保留实验位，上线验证无回归后，再单独一次提交删干净。

## 可行性验证（2026-10-20，纯读代码与既有测试，未改任何产品代码）

问题：整页导航到网关路径，对方机器的完整界面（侧栏、对话、审批、流式）能否正常工作？

结论：**可行**。三条依据：

- **路径前缀安全。** 网关在 `<head>` 最前注入 `<base href>`，并把页面里所有根绝对地址
  （`src`/`href`/`action`/`poster`）逐个改写到网关前缀下。既有测试钉死了这一条：base 在最前、
  原根地址一个不剩。这套机制原本服务于「嵌在主区」，但恰恰是路径前缀方案成立的前提。
- **前端没有自己的地址栏路由。** 在 DSH 的客户端包里找不到路由或改写地址栏的代码
  （会话选择走状态，不走路径），因此不存在「客户端自己把地址改回根路径」的冲突——这是路径
  前缀方案最常见的死法。
- **存储与 cookie 已按主机隔离。** 注入脚本把对方的 localStorage/sessionStorage 按主机分
  区，并把 `document.cookie` 的读写整个掐断（网关在服务端自己握着远端登录态）。这原本是为
  了在 iframe 里不污染父页面，整页导航下同样成立。

注入脚本本身不依赖父窗口：它只改 fetch、脚本地址和那条 WebSocket 通道，没有「找父页面说话」
的逻辑；服务端注入的 `uiWorkspace` 句柄在顶层没有读者，属无害冗余。

**仍未证明的只有运行时行为**（对方页面能否启动、WebSocket 能否连上、流式是否正常）。
这需要两台真实实例实测，属于实施阶段第 ① 批的验收内容。

## 机制

### 1. 侧栏停止遮蔽

现有的影子注册（`sidebar-tree.ts`）改为默认不注册。它本身不声明任何子插槽，所以「不注册」
不会与原生冲突；实验位开关的语义反转：`threadharbor.sidebarTree` 从「设为 `off` 才用原生」
改为「设为 `on` 才用影子树」，专门留给将来比较上游是否改进了子插槽转交机制。

不注册之后，主区里「在主区打开对方会话」的 iframe 也随之失去入口（它由影子树调用）。

### 2. 主机切换器

位置：侧栏底部动作区（设置按钮上方），用 `sidebar.footer.action` 这个列表座位，不占用
浏览区。形态是一个紧凑的选择器：当前主机名 + 展开后是「本机」与已登记主机，每行带在线
状态点与部署状态。

行为：点某台主机 → `location.assign` 到 `/threadharbor/gateway/<hostId>/`；点「本机」→
回本地根路径。地址栏是唯一真相，本地存储只用来让选择器记得上次选了谁（便于在回到本机时
显示上一次在哪台）。

离线或未部署的主机在列表里显示状态且不可点，附「到 设置 → 各主机 完成部署」。

### 3. 网关注入回本机入口

网关改写对方页面时，在注入脚本里追加一个很小的界面元素：侧栏顶部一行主机名，可点回本机。
它必须复用现有的注入通道（`<head>` 里 base 之后的那段脚本），不新增页面级改写，也不改动
对方的任何布局；样式自带，不依赖对方的样式表。

注入入口的可用性由宿主端测试覆盖（脚本能解析、元素存在、点击后地址回到本机根）。

### 4. 错误处理

网关目前对失败一律回 `text/plain`（未登记 404、路径不合法 400、令牌失效 502）。整页导航
会把这些裸文本直接甩到浏览器里，因此要为**页面导航**（`Accept: text/html`）改成一个小的
静态页面：一句原因（沿用现有措辞）、一个回本机的链接、一个到设置里的链接。接口请求仍走
现有纯文本响应，机器可读行为不变。

### 5. 退役跨主机汇总树

依赖已查清：影子注册、主区 iframe、那棵 798 行的树、七个远端动作代理、汇总逻辑、
轮询与远端会话存储，**只被它们自己和各自的测试引用**，外加浏览器入口那一处接线。
「各主机」设置面板是另一条线，独立保留。

按决策 6 分两步：第一步只把注册关掉（代码仍在），上线验证无回归；第二步单独一次提交删掉
那一簇连同六个测试文件。删除前重新查一次引用。

### 6. 不动的能力

手机配对面板、各主机设置区（含 SSH 部署与连通性检测）、GLM 配额胶囊、会话 id 复制条、
切换进度条、交接卡、丢失输入恢复、agent 探测、以及 ACP 接入层——全部不受本次改动影响。
