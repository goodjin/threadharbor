# ACP 会话补齐：让外部 agent 会话在界面与交互上对齐原生会话

> 状态：待审阅
> 日期：2026-10-13
> 范围：以外部 agent 为执行体的会话（`acp-*` 预设），补齐与 DSH 原生会话在
> 停止、可见性、历史、附件、提问、收尾上的差距。

## 1. 背景

ThreadHarbor 把外部 agent（claude / codex / grok / cursor 四家，经 ACP 协议）接进
DSH 会话：提问发出去、事件投影回来，但**回合驱动用的是插件自己的循环**，投影只覆盖
主链——于是用户会遇到一批原生会话没有的落差：

| 落差 | 现状 | 后果 |
|---|---|---|
| 停止生成无效 | 外部 agent 照跑到底 | 用户停不掉回合 |
| 工具卡只有终态 | 工具帧只在回合末落库、不增量 | 工具卡没有"执行中"，codex/grok 连中间帧都没有 |
| 重开/重启/换机后失忆 | 外部会话是独立的，DSH 里的转录与它无关 | 历史不回灌，agent 一脸茫然 |
| 图片附件被丢弃 | 提问只取文本块 | 用户以为图过去了，其实 agent 没收到 |
| agent 提问被跳过 | cursor 的 ask_question 自动答"无法服务" | 想问你的事你看不到 |
| 收尾不真 | 上下文占用靠猜、步数恒为 1 | 数字会误导 |

这些落差里，**停止**和**工具卡只有终态**两项优先级最高：前者让用户停不掉，后者让用户
在工具执行的过程里什么都看不见。

## 2. 目标与边界

**做**：让外部 agent 会话在**可停、可看、有记忆、收发附件、会提问、收尾不假**六件事上
对齐原生会话。

**不做**（明确排除）：

- 压缩 / 上下文整理那类行——那是 agent 自己的事，外部 agent 自管上下文，不做。
- 模型重试倒计时行——外部 agent 的重试不经我们，做不了真数字。
- 子 agent 的独立转录——四家都没有对应的协议，不造。
- 让外部 agent 的命令进 DSH 的终端面板（右栏）——见 6.4，刻意保持现状。
- 移动端专项（另按通用前端工作处理，不在本轮范围）。

## 3. 探针实测结论（四家矩阵）

2026-10-13 真机探针（对每个 agent 起真实 ACP 会话、直连 JSON-RPC，不经 DSH）：

| 能力 | claude | codex | grok | cursor |
|---|---|---|---|---|
| 取消当前回合（session/cancel） | 支持，3ms | 支持，32ms | 支持，44ms | 支持，5ms |
| 图片内容块 | **不支持**（服务端明确说没处理图像） | 支持 | 支持 | 支持 |
| 流式 | 支持，首帧 1.2s | 支持，首帧 10.2s | 支持，首帧 4.8s | 支持，首帧 3.2s |
| 工具帧形状 | 执行中→更新→更新→完成（四帧，跨约 3s） | 只有调用→完成（两帧） | 调用→完成（两帧） | 执行中→完成（三帧） |
| 命令怎么跑 | 工具帧里看得见 | 工具帧里看得见 | 工具帧照发，执行走终端子协议 | 工具帧里看得见 |

结论：取消四家都认；图片只有 claude 不收。**四家都发工具帧**，之前探针报的"grok/cursor
一条工具帧都没有"是探针自身的失误——它只留了前 12 帧，工具帧排在后面被切掉了，已修正。
真正的差距是：**claude/cursor 有执行中（多帧、有中间态），codex/grok 只有调用+完成两段**。
另外 grok 的工具帧之外还走终端子协议执行命令，但卡片照样有命令和输出，用户看得见。

## 4. 设计：能力表（骨架）

四家差异集中到一张表，所有修补只读这张表；表同时也是活测的输入，写错就红。

**位置**：`packages/dsh-acp-agent/src/dialects/types.ts` 的 `AcpDialect` 增加
`capabilities` 字段，四家方言各填实测值：

| 项 | claude | codex | grok | cursor |
|---|---|---|---|---|
| `cancelsTurns` | true | true | true | true |
| `acceptsImageContent` | **false** | true | true | true |
| `toolFrameShape` | `in_progress` | `two_frame` | `two_frame` | `in_progress` |
| `commandVia` | `tool_frame` | `tool_frame` | `tool_frame`（执行走终端子协议） | `tool_frame` |
| 工具名映射 | 见 6.3 | 命令行当名字 | 标题当名字 | 见 6.3 |

**驱动的行为**：取消发不发（四家都发，表留给第五家 agent 用）、图片拦不拦、工具帧
怎么增量投影、工具名映射到哪个视图键。终端子协议只是 grok 的执行机制，不影响可见性。

**防漂移**：活测（`packages/dsh-acp-agent/tests/live.spec.ts`）对每家断言这张表的值——
比如断言 claude 的 `acceptsImageContent` 为 false 时，图片用例必须出现"拦下"分支；
表写错哪格，对应那条当场红。

## 5. 设计：停止与中断

现状：回合驱动（`packages/dsh-preset-dispatch/src/dispatch.ts`）只拿到提问，拿不到
当前回合的中止信号，也不发取消通知，于是外部 agent 跑到底。

**改法**：

1. **拿到中止信号**：原生循环的中止信号在实例内部，被替换的那一步拿不到；但原生循环
的取消方法（`ReactLoopAgent.cancel`，`packages/interaction/core/src/agent.ts:175`）是
   公开的。在实例上包一层，把当前回合的中止信号记下来供 runner 读取。
2. **runner 监听信号**：`packages/dsh-preset-dispatch/src/runner.ts` 的 `AcpTurnRunner.run()`
   监听中止信号；一旦中止立刻发 `session/cancel` 通知，之后到达的结果一律丢弃，回合
   按中止落账。当前是"等外部 agent 跑完再落库"，要改成"中止信号到就收尾，外部 agent
   之后送来的东西不再写进会话"。
3. **界面语义**：停止按钮和 Esc 立刻生效；忙碌时的补充与排队照常，补充要等这个回合
   真正收尾才会被取走。

**边界**：用户中止后、外部 agent 自己随后结束（比如用户按了停止、agent 几秒后自己跑完）
——这种情况回合**按中止落账**（用户按了就按了），中止之前的内容保留，中止之后到达的
结果丢弃。

## 6. 设计：工作可见性

### 6.1 工具帧改为收到即写

现状：回合末一次性写所有工具卡（`content-writer.ts` 收齐再写）。

改法：投影收到工具帧就写——

- **claude**（`in_progress`）：收到执行中帧写一条调用，之后更新帧就地改这条，收到
  完成帧写结果。
- **codex**（`two_frame`）：收到调用帧写调用，收到完成帧写结果。卡片会呈现"已发出、
  已完成"两段，中间是空的——照实呈现，不假装 codex 有执行中。
- 配对靠调用编号：**编号在回合内唯一**；跨回合如果重复，编号前加回合号兜底（活测覆盖）。

### 6.2 终端子协议：记录事实，不做可见性补丁

grok 执行命令走 `terminal/*` 子协议（create / output / kill / release /
wait_for_exit），由进程内的终端服务代答（`packages/dsh-acp-agent/src/terminals.ts`）。
它同时照发工具帧、工具帧里带着命令输出，所以**用户看得见命令和输出，不存在黑盒**；
终端子协议只是执行机制，不需要额外投影成转录行。

**刻意保持**：这些命令不进 DSH 的终端面板（右栏）——让外部 agent 的命令进 DSH 终端
面板会顺带引入 DSH 的权限与环境拦截，改变现有执行路径；工具帧承担可见性已经够用。

### 6.3 工具名映射（命中专用视图）

投影时把 agent 报的工具名规范化成 DSH 的工具视图键（`Read`→`read`、
`Edit`→`edit`、`Bash`→`bash`、`TodoWrite`→`todo` 等），命中的出专用视图（读文件、
编辑 diff、命令卡、待办），命不中的落通用卡。映射表按方言走，并进能力表。

副作用：权限预设按 DSH 的工具名匹配，映射后自然命中。

## 7. 设计：历史回灌

**触发**：外部会话第一次开之后、第一条提问发出之前，如果该 DSH 会话已有转录，把
转录整理成"之前对话"文字，随第一条提问发出去。机制已存在（换 agent 时的 primer 就是
这个），只需把触发条件从"只有切换时"扩到"外部会话首开且已有转录"。

**内容**：用户消息、助手正文、工具调用的标题与结果（每条结果截断，最多五百字）。
轮次整段全量、不省略（用户选的全量），只有工具输出截断。

**被拒路径**（用户明确要求）：agent 拒收（返回错误，或自己说"上下文装不下"），在
转录里写一行"历史回灌被拒绝"并说明原因，用原生已有的错误行样式——让用户看得见，
而不是对着失忆的 agent 干瞪眼。

**成本**：长会话首条提问很长，一次请求又贵又慢——全量回灌的代价，照做，规格写明。

## 8. 设计：输入框附件

- **图片**：按能力表分流——codex/grok/cursor 发图片块；claude 拦下不发，在输入框旁
  明说"这个 agent 收不到图片，未发送"，图片仍留在转录里并标记未送达。
- **文件附件**：本轮探针只验了图片，没验文件块。文件块暂不发，同样明说"附件未送达"，
  与图片共用一条规则；等实测确认 ACP 的文件内容块支持后再放开。
- **文本附件**：照旧（提问本来只取文本块，行为不变）。

## 9. 设计：agent 提问（cursor）

cursor 已确认会问（`cursor/ask_question` 扩展方法）。改成桥到 DSH 的提问服务
（`ui-user-questions` 的 pending question / host 的 ask service），用户答了回传。

其他家的提问形状未实测：先记账保持现状的自动应答，实测后再接。

## 10. 设计：近似项与收尾

| 项 | 做法 |
|---|---|
| 上下文占用近似 | 能算才算：agent 报了每轮输入 token 就算（codex/claude），拿它加上下文窗口估算并标注"估算"；grok/cursor 没这个数就显示"无数据"，不拿历史累计硬凑 |
| 统计 pill | 步数如实显示（外部 agent 内部多步不计），不造数字 |
| 模型清单 | 把方言的运行时读模型接进目录适配器（现在只读配置） |
| 错误行文案 | 连接类→重连提示、权限类→审批提示，其余显示原始串 |
| 插件文案 | 进度条、交接卡写死的中文改走 DSH 的 locale 字典，过 `verify-client-ui-i18n` |
| 命令终端面板 | 不进（6.2），可见性由工具帧承担 |

## 11. 验收

活测扩到四家（`packages/dsh-acp-agent/tests/live.spec.ts`，默认跳过，
`THREADHARBOR_LIVE_ACP=1` 跑），断言：

1. **取消**：发取消后回合在 5 秒内结束、停止原因为 `cancelled`、中止之后的内容不落库。
2. **图片**：codex/grok/cursor 正确读出测试图四个象限的颜色；claude 出现"拦下"分支。
3. **工具帧增量与形状**：claude/cursor 出执行中态且更新帧就地生效；codex/grok 出
   调用+完成两段；grok 的工具帧里带着命令名与输出。
4. **流式**：首帧时间、帧数与探针记录相当。
5. **历史回灌**：重开会话能答出上一段对话的内容；被拒时出现"历史回灌被拒绝"行。

**能力表是活测的输入**——表写错哪格，对应那条当场红。

## 12. 风险与取舍

- **回灌超窗**：长会话首条提问可能超 agent 窗口；已设计"被拒路径"，但代价是那次
  提问拿不到历史。取舍：宁可让用户看到"被拒"，不静默。
- **增量写库的时机**：工具帧增量写后，回合中途崩溃/中止要能清理到一半的调用；
  中止后到达的帧必须被丢弃而不是补写（5 节）。
- **cursor 的工具帧形状已实测**（`in_progress`），不再待确认；能力表里若与实际不符，
  改表一处即可。
- **近似指标的诚实性**：上下文占用、步数都标注或如实呈现，宁可缺数字不造假数字。
