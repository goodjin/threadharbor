# 2026-10-20 · 桌面版输入框的模型名没有 agent 名：我们的座位接管在新版契约下静默失效

## 问题描述

桌面版里选外部 agent（GLM-5.3 等），输入框按钮上只有裸模型名，看不出是谁在回答；
web 实例上同一个模型是带 agent 名的。用户反馈：桌面版重启应用后仍然如此。

## 现场证据

- **不是「客户端缺席」事故**（2026-10-20 早些时候那次）：桌面版页面里的插件清单含
  `@threadharbor/dsh-client/client.js`，渲染进程的编译缓存里也有它的记录——我们
  的客户端包确实加载了。
- 两边是同一个 DSH 版本（0.2.1-rc.2），客户端注入的依赖都在；退路开关
  `threadharbor.modelSeat=off` 没被打开（localStorage 里只有 `threadharbor.tree.*`）。
- **官方 0.2.1-rc.2 改了座位契约**：模型座位现在多声明了一个子座位
  `conversation.input.model.label`，可见的模型名由这个子座位渲染（没有占用者时
  回退成裸模型名），而占用者是另一个插件（`dsh-client-ui-deepseek-model-label-1017`）。
  上游给这个子座位写的正是扩展点说明。
- **我们那份是 0.2.0 时代的整份拷贝**（`composer-model-select.tsx`，照 DSH 0.2.0-rc.2
  抄的）：它整个替换模型座位、自己内联画标签，把上面那套新机制整个绕开了。
- **更要命的是它靠一次性读取决定要不要注册**：挂载那一刻读 `ctx.get('modelDirectories')`，
  读不到就**静默不注册、也不重试**。桌面版上那次读取恰好没拿到服务 → 官方座位顶上
  → 界面上只剩裸模型名；web 上读到了 → 我们那份赢 → 有 agent 前缀。同一个构建，
  两种表现，而且**全程不报任何错**。

## 根因分析

两件事叠在一起：

1. 座位契约在 0.2.1-rc.2 变了（可见标签移到子座位），我们那份照旧版本抄的拷贝
   骑在新机制上面，两边对不上；
2. 我们的注册是**一次性读取 + 顺序依赖**：读不到服务就静默放弃，于是「装没装上」
   取决于客户端模块的装载顺序——这正是同一份代码在 web 上好、桌面版上坏的原因。

## 修复方案

- **不再整体替换模型座位**，改成只占官方声明的那个**标签子座位**：
  - 子座位由官方声明，`slots.inject` 等它出现 → **顺序无关**，装载顺序不再决定成败；
  - 标签的 props 里就带着 provider（`{id,name}`）与 model，agent 名字直接从 provider 拿
    → 不再需要模型目录服务，那条「读不到就静默」的路整个消失；
  - 座位本身仍由官方那份渲染（两段式菜单、搜索、强度选择、提示都还是官方的），
    我们那份 0.2.0 的拷贝（687 行）随之删掉，也就不用再跟着 harness 升级重抄。
- 官方那个 1017 角标（只对官方 Flash 的某个固定版本）由本组件复刻：我们接管了座位，
  就不把它弄丢。
- 退路开关 `threadharbor.modelSeat=off` 保留：设成 off 时我们不注册，官方标签原样。

## 验证步骤

- 新增 `model-label.spec.ts`：注册在标签子座位上、优先级低于官方占用者、**等子座位
  出现才注册**（顺序无关）、撤掉之后官方那份回到原位、开关为 off 时不注册；
  前缀规则（外部 agent 路由加前缀、原生 provider 不加、模型名已带 agent 名则不加）；
  1017 角标复刻与不误挂。
- 挂载用例的假座位核补上这个子座位的声明（官方 model-selection 那份注册会声明它）；
  两条与「模型入口」相关的旧用例改写成新契约（占标签子座位；模型目录服务缺席也照样挂载）。
- 全仓 `npm run typecheck` + `npm run test`（1883 个用例）通过；`npm run build` 通过。

## 遗留与提醒

- 我们的 devDependency 仍把 DSH 客户端包钉在 **0.2.0-rc.2**（跑的是 0.2.1-rc.2），
  所以那个子座位名没有类型可钉；护栏是运行时那一道——注册进没人声明的座位会当场
  炸出来（挂载用例里的假座位核就是照这个立的）。把钉版本提到 0.2.1-rc.2 之后，
  座位名可以重新被类型钉住。
- 构建的新鲜度门禁（`scripts/check-freshness.mjs`）原先拿**时间戳**判断产物新不新：
  入口的编译产物去比它引用的每个源文件。两头都错——内容没变但文件被重写
  （git checkout、编辑器保存同内容）会误报，唯一的绕法是清库重建；而清库期间
  `lib/` 是空的，桌面版从磁盘现读现服务客户端包，那个窗口里刷新页面就读到半成品
  （2026-10-20 桌面版现场：输入框连模型都不见了）。现在门禁**问 tsc 自己**
  （`tsc -b --dry`：它按内容哈希判断，会说「A non-dry build would build …」），
  与编译器自己的判断不会分歧，误报也没了。
