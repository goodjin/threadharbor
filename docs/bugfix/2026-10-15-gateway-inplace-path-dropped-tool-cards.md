# 2026-10-15 · 选了外部 agent 只看到回答、看不到过程：就地回答这条路把工具卡片扔了

## 问题描述

会话里选 Claude / Cursor / Codex / Grok 作模型，回答正常，但界面上从来看不到
它跑过什么命令——只有一段思考和最终答复。原生模型选的会话却有完整工具卡片。

## 现场证据

扫了所有会话日志，按「真正由该 provider 应答的回合」筛：

- 每一个 `acp:acp-claude` / `acp-cursor` / `acp-codex` / `acp-grok` 的回合，
  工具卡片数都是 **0**；
- 唯一有数的是 `acp:acp-zcode`（走原生循环的那条路）。

最能说明问题的是一个 Grok 回合：回合**成功完成**，助手消息里带着思考，正文写着
「正在把连接器分支合入 dev」——那必然执行了 git 命令，可整份会话里找不到一次
工具卡片。

对照：同一套 runner 走**接管**那条路时，Claude 探针会话的工具卡片是齐的。

## 根因分析

外部 agent 有两条应答路径，只有一条接了工具卡片：

- **接管整个回合**（session 归本行管）：把宿主真正的写入器交给 runner，卡片照写；
- **就地回答**（本行的模型被原生会话选用）：给回合的写入接口是**空实现**，
  runner 生成卡片往那儿写，写完就丢。

代码里写着「原生循环负责持久化，网关不写任何东西」，前提是循环会从流里写出一切。
但工具卡片是 **log-only** 事件，根本不在循环拼消息用的那套流词汇里——循环看不见
它们，也就不可能替它写。这个前提是错的，于是工具卡片被静默丢弃，且**不报任何错**。

设计文档（2026-10-13 原地回答对齐设计）本来就要求工具卡首帧即写、且
「用户看得见命令和输出，不存在黑盒」——实现与意图相反。

## 修复方案

就地回答这条路从宿主取出该 DSH 会话的写入器，按回合交给 runner：

- 写入器**只放工具事件**（`tool/call`、`tool/result`，以及「附件未送达」的展开），
  **丢开助手消息**——消息是循环从流里拼出来写的，这里再写一份就是同一步两条消息，
  而会话视图只留最后一条，会把用户刚看着到达的那条抹掉。
- 结果事件仍按「回合号 + 调用编号」指回它回答的调用，不会成为孤儿。
- 拿不到写入器的主机上照常作答，只是卡片无处可去——不拿可见性换可用性。
- 位置仍是占位值：卡片的落位由它在日志里处于哪个 `turn/start`／`step/start` 边界
  之间决定，不看卡片自带的回合号（读 reference `ui-chat/.../tool.ts` 的
  `locationTurn` 确认）。
