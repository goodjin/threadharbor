# 静默看门狗为声明超时的工具让路（qoder gradle 编译被误杀）

## 现象与证据

会话 `session-2c030c08-bade-47ce-b986-95cc6c87763e`（glasses/phone 工作区，qoder/dfmodel）
第 16 回合于 2026-10-30 12:59:10 以 `ACP_STALLED`（静默 300s）收场，最后一条工具结果
「结果未知」，整回合作废；用户重发的消息进了重开的新会话。

三方原始数据核对（DSH 会话日志、qoder 段日志、qoder 任务输出）：

- **12:54:05** qoder 发起 `./gradlew :expo-realtime-audio:compileDebugKotlin`（声明
  `timeout: 600000`，输出接 `tail -25`——完成前零字节流出）。
- **12:54:10 → 12:59:10（静默窗口）**：qoder 段日志 **0 行**（工具执行只在
  开始/结束各写一行）；无任何 ACP 帧（qoder 执行工具期间不发帧）；无流式输出
  （tail 缓冲）。看门狗的三个信号（帧、文字流、日志行）全部天然为黑。
- **12:59:10.697** 看门狗（`stallMs: 300000`）杀掉进程树：`tool.shell.finished
  exit_code=143 signal=15 aborted=true`。段日志里 12:59:10.8 的收尾行是死亡级联
  （SIGTERM → 杀子进程 → 记 aborted），不是编译完成。编译在跑了 305 秒后被杀，
  距它声明的 600 秒预算还差 295 秒。

对照：同会话 12:28–12:33 的一次上下文压缩期间段日志同样 282 秒无新行，仅以 18 秒
之差躲过期限——「工具/压缩长跑 + 三个信号全黑」是同一类结构缺口，这次踩实了。

## 原因

看门狗把「无帧、无日志新行、无输出」判为 agent 挂死，但**长跑的工具**在这三条上
与挂死无法区分。工具自己声明的超时预算（qoder 的 Bash 参数里就带着
`timeout: 600000`）是现成的、agent 申报的信号，此前没有被使用。

## 修复

- **方言可选钩子 `toolTimeoutMs`**（`args → 声明超时 ms`）：只有 qoder 实现
  （Bash 参数自带 timeout）；其余方言不实现，看门狗行为与之前完全一致。
- **runner 记账**：每个工具调用首次被看见的时刻；`openToolDeadline()` 给出未收尾
  工具里最晚的「首见时刻 + 声明超时」（已收尾的不计；取 max 覆盖并行工具）。
  记账随 prompt 生命周期清空。
- **看门狗让路**：`fireStall` 在预算未耗尽时重挂静默定时器到预算后 50ms，不收场、
  不计为活动（`crashNote` 的「整轮零输出」口径不受影响）；预算耗尽或工具收尾
  （收尾是活动，正常重挂期限）才按静默收场。**总上限（`totalMs`）不变**——
  一个再也不回来的工具最多被让到总上限（默认 30 分钟）。
- 按本次现场回推：该编译的预算截止约在 13:04:05，看门狗会让路到那一刻；编译若在
  预算内完成，收尾帧是活动，回合正常继续。

## 验证

- 方言：`dialects.spec` 钉住 timeout 读取与缺省/非数字/非正数的边界。
- runner：`runner.spec` 钉住「带超时的未收尾工具给出预算截止、收尾后清零」与
  「无钩子（codex）或参数无 timeout 时没有预算」。
- 网关：`gateway.spec` 钉住两阶段——预算内静默不收场（3s 期限过后回合仍活着），
  预算耗尽后按真实静默时长（≈4s，非 3s）以 `ACP_STALLED` 收场并丢弃会话。
- 全仓 `npm run typecheck` 与 `npm test`（2160 个测试）通过。改动只在
  `dsh-acp-agent`（方言层）与 `dsh-preset-dispatch`（runner/网关）——两者宿主侧
  从 TS 源码直接加载，无构建产物；未触碰 `dsh-client`。桌面重启应用后生效。
