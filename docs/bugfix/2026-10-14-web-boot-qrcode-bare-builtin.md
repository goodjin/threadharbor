# 2026-10-14 · 3081 再度拒载：二维码库把裸名字的 fs 带进浏览器包

## 问题描述

合并手机配对功能后，打开 `http://127.0.0.1:3081` 报：

> Failed to load plugins · @threadharbor/dsh-client
> web boot: 1 entry did not activate
> import failed: client-modules: require("fs") missed the module table

页面装载器只认自己的模块表（平台种子词、已物化插件、注册的包工厂），任何
require 落空都整页拒载。

## 现场证据

- 对产物做字节扫描：混进来的不止 `fs`，而是 `assert、buffer、fs、stream、
  util、zlib` 一整条链——正是 PNG 编码（zlib 压缩、buffer 拼流）的依赖形状。
- 定位到包体里 `qrToImageData` / `getImageWidth` 一段：手机配对面板引入的
  `qrcode` 库，其包主入口按 Node 解析，连带打包了"把 PNG 写到磁盘"的渲染器，
  那个渲染器顶层就 `require('fs')`——裸名字，不带 `node:` 前缀。
- 昨晚（8c3b736）加的构建门只拦 `node:` 前缀的字样；裸名字在压缩后调用名被
  改写、只剩参数字面量，恰好漏网。烟测里伪造的 require 也只拒绝 `./` 与
  `node:` 开头，对裸名字返回万能假件，等于给坏包盖章。

## 根因分析

两层叠加：

1. **源头**：打包器没有采用 `qrcode` 自己声明的浏览器入口（包内 `browser`
   字段映射到 canvas 渲染版），按主入口整包打进浏览器图。
2. **门禁**：builtin 检查只认 `node:` 前缀这一种写法，存在第二种写法
   （裸名字）就静默放行。同一个错误以新拼写绕过了只升不降的检查底线，
   说明底线本身枚举不全，而不是某一处代码疏忽。

## 修复方案

三层同时收紧，任何一层再漏都有下一层兜住：

1. **解析侧钉死**（tsdown 客户端构建配置）：把 `qrcode` 按名定点映射到包
   自带的浏览器入口（canvas 渲染、无 fs）。源码与 Node 测试继续用包的
   正常入口，行为不变。
2. **门禁收紧**（verify-build）：内置模块清单改用 Node 官方
   `builtinModules` 全集，两种写法都拦——`node:xxx` 字样，以及"唯一参数是
   引号包裹的内置名"的调用形状（压缩只改调用名，参数字面量必然幸存）。
3. **烟测收紧**（同一脚本里的装载烟测）：伪造 require 对裸内置名同样抛
   "missed the module table"，与真实装载器行为对齐。

## 验证步骤

- 用新门先跑修复前的旧产物：正确变红，一次点名全部六个内置名。
- 重新构建后走完整链：类型检查、956 个测试、构建、四道校验门全绿；
  产物字节扫描无任何内置模块调用形状，canvas 渲染器在位。
- 重启 3081：启动日志再无 "did not activate"；带页面令牌实际取回浏览器
  下发的脚本，与本地干净构建逐字节一致（仅服务器补的 sourcemap 指针不同），
  脚本内无 `fs`。

## 相关测试

- verify-build.mjs 的两处 builtin 拒绝路径（字样与调用形状、烟测桩）。
- 手机配对面板自身的"真件画 PNG"回归：走包正常入口在 Node 下依旧通过，
  证明修复没有改掉测试所覆盖的行为。
