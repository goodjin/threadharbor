# Claude 会话选择与项目默认 Agent 修复

## 问题

- Claude 已在主机设置中完成配置，但新建会话的 Agent 列表没有 Claude。
- 新建会话每次都要求重新选择 Agent，没有沿用同一项目最近使用的 Agent。

## 根因

客户端与网关共用了“已安装、已登录、有会话适配器”这一通用判断。Claude 使用配置文件提供凭据，不存在交互式登录状态，因此旧版 hostd 返回的 `authenticated: false` 会错误地把它排除。新会话草稿的选择值则固定初始化为空，没有读取项目会话历史。

## 修复

- 在协议层统一 Agent 会话可用性规则：Claude 只要求已安装且会话适配器可用；其他 Agent 仍需认证。
- 客户端 Agent 列表、状态指示和网关创建校验共用该规则。
- 新会话优先选择同项目最近创建会话使用的可用 Agent；该 Agent 已不可用时选择列表第一个。
- 会话草稿打开期间若主机清单刷新，会保留仍然可用的手动选择，并在当前选择失效时回退。

## 验证

- 协议测试覆盖 Claude 无登录状态仍可用及其他 Agent 仍需认证。
- 网关测试覆盖 Claude 创建成功、未认证 Codex 创建失败。
- 客户端测试覆盖同项目最近 Agent、不可用回退、无历史回退和空列表。
- 类型检查、构建和相关测试通过后交付。
