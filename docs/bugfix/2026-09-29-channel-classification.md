# 通道状态分类收紧：够不着记黄、确实没了才记红；被取代记 superseded；删掉「已关闭」死状态

## 问题描述

状态机盘点（`docs/session-states.zh.md`）B5 / C7 / C8 三项定案（方案取「收紧语义、字段不动」）：

1. **红黄分类错误。** 主机够不着（网络断、服务没起、超时）这种**临时**故障被记成红的
   「已丢失」，看起来像「这个会话的记录没了」，要用户去点重开；等下一次调用成功又变绿。
   红条闪一下就走，状态跳变显得随机。
2. **自愈口径不统一。** 盘点原写「lost 投影即消、reconnecting 不消」，动手前逐点核对源码
   发现该说法不成立：每个写 lost 的地方都同时作废绑定，读取与推送两条内容路径都拒绝失效
   绑定——那条自愈规则是够不着的遗留死代码。真正定下来的口径应是：**红黄只被「真正碰到
   通道的调用」（重连/重开/发消息成功）清掉，日志投影一律不清**。理由：日志是 hostd 盘上
   的记录，Agent 通道死了照样读得到内容（用户现场录屏里的「远程 Agent 已停止」行就是进程
   死后从日志读出来的），内容到达不能证明通道活了。
3. **「被新代际取代」被记成 lost（绑定状态）。** 旧实例作废、记录本身好好的，语义应是
   superseded。
4. **closed 是死状态。** 生产代码从未赋值，客户端却有「会话已关闭」分支。
5. **中断口径张冠李戴。** 一处结论行固定写「远程 Agent 进程已停止」，哪怕真正的原因是
   主机够不着；两条通道横幅还借用全局连接错误当原因。

## 根因分析

- 失败分类器只把「超时/连接中断」当成「主机没应答」，把**纯连接失败**（连接被拒、管道
  断、fetch failed）归到「有答案」一侧，于是记红。区分点其实是「主机有没有回话」：回话了
  并且说坏消息（记录没了 / hold 进程的套接字没了 / 有冲突要处理）才需要人修；链路本身没
  通是暂时的，会自己好。
- 自愈规则按「有没有读到内容」判断，而内容的来源（日志）与通道死活无关。

## 改动

- 分类收紧（网关）：纯链路失败（连接被拒、管道断、ENOTSOCK、fetch failed，且错误里没有
  指名 hold 套接字 / 命名管道）记「暂时够不着」；主机回话说坏消息才记「已丢失」并作废绑定。
  消息没送达的处置按同一条线分开。裸 ENOENT 归「有答案」——hostd 报工作目录不存在和套接字
  不存在是同一种写法，保留更准的诊断。
- 自愈统一（网关折叠收尾）：红黄一律不因日志投影改变，只有碰到通道的调用才清；connecting
  是准入态，首次同步完成即转正常。删掉那条够不着的旧规则，注释写明理由。
- 代际被取代（网关三处：attach 返回、restart 返回、日志页代际不符）绑定记 superseded，
  通道仍按「要修复」处理；记录没了 / 进程没了 / 日志缺口仍记 lost。
- 删除 closed：协议类型、网关存储校验、客户端解析列表与展示分支。
- 文案分开：中断的结论行按「Agent 进程没了」与「主机暂时联系不上，本轮已中断」分说；
  两条通道横幅改为固定文案（「暂时联系不上远程主机，正在自动重试…」「远程主机上这个会话
  已不可用（记录没了、Agent 进程没了或被新实例取代）…」），不再借用无关的连接错误。

## 验证

- 新增回归测试：gateway.spec「marks a message that never reached the host as a reconnecting
  channel, not a lost session」（红黄分类）、「records a replaced generation as superseded,
  not lost」（取代语义）、「says in the record whether the Agent died or the host merely went
  unreachable」（中断口径分开）、「does not clear a lost session from journal content — the
  repair call does that」（自愈口径守卫）；conversation-model.spec 通道横幅文案与「不借用
  连接错误」。
- 既有断言随口径更新一处：「fails a running turn when the hold worker is unreachable」的
  结论行现在按「主机暂时联系不上」记（它的模拟错误就是纯连接被拒，原来正是张冠李戴）。
- 全量 490 个测试通过（37 个文件）；`npx tsc -b tsconfig.json` 与 `npm run build` 干净。
